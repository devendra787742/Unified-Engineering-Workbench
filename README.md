## Main modules

### 1. Geometry and temperature visualization
- Loads the included ASCII STL unit-cube model.
- Displays an interactive 3D mesh preview with rotate, pan, zoom and fit controls.
- Loads nodal temperature CSV data and displays a 3D point-cloud preview with a temperature legend and node inspection.
- The example STL is self-created and contains 12 triangles.
- The example temperature dataset is synthetic; it is **not** an ANSYS export.

### 2. Thermal finite-element analysis
- One-dimensional steady-state thermal FEA using two-node linear elements.
- Supports the assignment meshes: 10, 20, 40 and 80 elements.
- Uses prescribed endpoint temperatures and insulated lateral surfaces.
- Compares the finite-element midpoint result with the analytical solution.
- Exports numerical results to CSV.

Model parameters:

| Parameter | Value |
|---|---:|
| Length, L | 1 m |
| Area, A | 1 × 10⁻⁴ m² |
| Conductivity, k | 10 W/(m·K) |
| Volumetric heat generation, q | 10,000 W/m³ |
| Left boundary, T(0) | 100 °C |
| Right boundary, T(L) | 20 °C |

Governing equation:

`-d/dx(k A dT/dx) = q A`

Analytical solution:

`T(x) = 100 - 80x/L + [q/(2k)]x(L-x)`

The model assumes constant material properties and one-dimensional heat flow. Lateral surfaces are insulated. Endpoint temperatures are imposed directly through elimination of the prescribed degrees of freedom.

### 3. CPU performance benchmark
- Runs the same deterministic batch cases in serial and with a bounded CPU worker pool.
- Uses a fixed random seed and preserves result ordering.
- Compares serial and parallel outputs.
- Reports wall-clock execution time, speedup and parallel efficiency for worker counts 1–4.
- The recorded candidate-machine run achieved approximately **3.135× speedup at 4 workers**, with zero observed serial/parallel result difference in that run.

Benchmark values are machine- and run-dependent. The 3.135× result is an observed run, not a universal performance guarantee. The required five-measurement median evidence and complete hardware metadata should be added to the final benchmark record before submission.

### 4. Embedded-system integration (simulated)
- Includes mock MCU, FPGA and JTAG adapter workflows.
- Demonstrates connection status, simulated telemetry and disconnection.
- Includes a recoverable FPGA timeout scenario.
- No physical MCU/FPGA/JTAG hardware is connected or programmed.

JTAG is represented as a debug/programming transport interface; it is not treated as a compute board.

### 5. Backpropagation demonstration
- Implements the specified single-sample tanh network and squared-error loss.
- Computes analytic gradients and performs simultaneous parameter updates.
- Checks analytic gradients against central finite differences.
- Exports the 100-step loss history to CSV.

## Build from source on Windows

### Prerequisites

- Windows 11 x64
- Node.js LTS and npm
- CMake
- Visual Studio 2019/2022 Build Tools with the C++ workload and Windows SDK
- Git (recommended)

### Build and package

Open **x64 Native Tools Command Prompt for Visual Studio**, change to the repository directory, and run:

```bat
scripts\build_desktop_windows.bat
```

The script builds the C++ backend and desktop package. The installer is written to:

```text
release\Unified-Engineering-Workbench-Setup-1.0.0.exe
```

To build/test the C++ core separately:

```bat
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build --output-on-failure
```

Use the desktop build script for the integrated Windows application. The C++ CLI can also be run directly from its build output when required.

## Input formats and data provenance

### ASCII STL
The importer accepts ASCII STL facet/vertex data. The included `data/unit_cube_ascii.stl` is a self-created unit cube with 12 triangles. Native CAD solids and binary STL are outside the current example scope.

### Temperature CSV
Expected header:

```csv
node_id,x_m,y_m,z_m,temperature_C
```

Coordinates are in metres and temperature is in degrees Celsius. The included five-node sample is self-created synthetic data, not a real ANSYS export.
